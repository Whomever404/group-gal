# 05 · 依赖关系与运行方式

> **一句话结论**：这是一个 Vite + TypeScript 工程，开发时用 `npm run dev`，交付时用 `npm run build` 产出自包含单文件 `dist/index.html`；玩家侧**零依赖**，双击即玩、离线可玩。

本文覆盖：怎么装、怎么跑、怎么校验、怎么打包、出问题怎么办。

---

## 1. 环境要求

| 项目 | 要求 | 说明 |
|------|------|------|
| Node.js | **建议 ≥ 20** | 见下方「依据」。实测于 **Node v24.1.0** 通过 |
| npm | 随 Node 附带即可 | 实测 **npm 11.4.2** |
| python3 | 可选 | 仅 `./start.sh` 用它起本地静态服务器；缺失时退回 `file://` 直开 |
| 浏览器 | 现代浏览器 | 产出是纯 HTML/JS/CSS，不需要任何运行时库 |

**版本依据**：`package.json` **没有 `engines` 字段**，因此 Node 版本没有硬性约束，上面只是**建议**。

- `devDependencies` 里声明了 `vite@^7.0.0`（本次实测解析为 vite `7.3.7`），Vite 7 官方要求 **Node 20.19+ / 22.12+**；
- `tsx@^4.19.2`（跑 `check:script` / `smoke`）同样要求现代 Node；
- 因此写「建议 Node ≥ 20」，并非硬性门槛——低于此版本时 Vite/tsx 可能直接拒绝启动。

> 想看确切的版本区间，以 Vite 7 与 tsx 的官方文档为准；本项目未锁定 `engines`。

## 2. 依赖一览

`package.json` 的 `devDependencies`（全部为**开发/构建期**依赖）：

| 包 | 声明版本 | 作用 |
|----|---------|------|
| `vite` | `^7.0.0` | 开发服务器（HMR）＋ 生产构建（实测 vite `7.3.7`） |
| `vite-plugin-singlefile` | `^2.1.0` | 构建时把 JS/CSS **内联**进单个 HTML（见日志里的 `Inlining: …`） |
| `typescript` | `^5.7.2` | 类型检查（`tsc --noEmit`），配置为 `noEmit`，不产出任何文件 |
| `tsx` | `^4.19.2` | 直接运行 TypeScript 脚本（`check:script`、`smoke`） |
| `jsdom` | `^29.1.1` | 在 Node 里加载构建产物、驱动玩法（`check:build`） |
| `@types/node` | `^22.10.0` | Node 类型声明（`tsconfig.json` 的 `types` 含 `node`） |

**运行时零依赖**：构建产物是自包含单文件——JS、CSS、立绘（内联 SVG）全部内联，`http(s)://` 外链只有「关于/素材」页里的 BGM 来源署名（点击才访问）。玩家侧**不需要任何库，也不需要 Node**。

## 3. 命令表

来自 `package.json` 的 `scripts`（**名称逐字一致**）：

| 命令 | 实际执行 | 作用 | 何时用 |
|------|---------|------|--------|
| `npm run dev` | `vite` | 开发服务器 + 热更新 | 改代码、边改边看 |
| `npm run build` | `npm run check:script && vite build` | **先校验剧本，再**构建单文件 | 出交付物 |
| `npm run preview` | `vite preview` | 预览已构建的产物 | 构建后本地看一眼 |
| `npm run typecheck` | `tsc --noEmit` | TypeScript 零错误检查 | 提交前 |
| `npm run check:script` | `tsx src/engine/validate.cli.ts` | 剧本图校验 | 改剧本后 |
| `npm run smoke` | `tsx tools/smoke.ts` | 无头引擎测试 | 改引擎/剧本后 |
| `npm run check:build` | `node tools/boot-check.mjs` | 用 jsdom 加载产物跑端到端 | 构建后 |

**`build` 为什么先跑 `check:script`**：剧本图校验器（`src/engine/validate.ts`）是**构建前置**。跳转写错、角色键拼错、Bad End 缺文案、节点不可达都会让构建**直接失败**，而不是等玩家在游戏里踩到。所以 `build` 的第一件事就是跑 `check:script`——它挂了，`vite build` 根本不会执行。

## 4. 三种游玩方式

| 方式 | 命令 / 操作 | 适合 |
|------|-----------|------|
| A. 本地服务器 | `./start.sh [端口]` | 想要一个 URL、多设备访问 |
| B. 直接双击 | 双击仓库根目录的 `group-chat-galgame-v2-modular.html` | 零环境，最快 |
| C. 开发模式 | `npm run dev` | 改代码、有 HMR |

### 方式 A：`./start.sh`

```bash
./start.sh          # 默认端口 8931
./start.sh 9000     # 换端口
```

`start.sh` 会：

1. **优先用构建产物** `dist/index.html`；若不存在，**退回**仓库根目录提交的单文件副本 `group-chat-galgame-v2-modular.html`（双保险）；两者都缺则报错提示先 `npm install && npm run build`；
2. 打印两个入口（`file://` 直开链接 + `http://localhost:<端口>/…`）；
3. 用 Python3 自带 `python3 -m http.server` 起服务（无需任何依赖）；没装 python3 时提示直接用 `file://` 链接。

```
▶ 单文件版（离线）: file:///workspace/dist/index.html
▶ 本地服务器    : http://localhost:8931/index.html
```

### 方式 B：直接双击单文件

双击根目录的 **`group-chat-galgame-v2-modular.html`**（它就是 `dist/index.html` 的副本）即可开玩，`file://` 下所有功能可用。

### 方式 C：开发模式

```bash
npm install
npm run dev
```

### ⚠️ 最容易踩的坑：`index.html` **不能**直接双击

仓库根目录的 `index.html` 是 **Vite 的开发入口**（`<script type="module" src="/src/main.ts">`）。用 `file://` 直接双击打开它，模块会加载失败，于是页面在约 1.2 秒后显示一段**兜底提示**：「这是一个开发入口，不能直接双击打开」。

这是**预期行为**，不是 bug。想开玩请用：

- `./start.sh`（方式 A），
- 双击 `group-chat-galgame-v2-modular.html`（方式 B），
- 或 `npm run dev`（方式 C）。

## 5. 构建产物

```bash
npm run build
```

实测输出（节选）：

```
角色 16（可攻略 15）　·　节点 1249（label 165）　·　坏结局 23　·　角色线 15
剧本校验通过：1249 个节点，0 个警告
vite v7.3.7 building client environment for production...
✓ 50 modules transformed.
[plugin vite:singlefile] Inlining: index-BqYstsOG.js
[plugin vite:singlefile] Inlining: style-DpzLWZ7F.css
dist/index.html  145.05 kB │ gzip: 52.29 kB
✓ built in 419ms
```

| 项 | 实测值 |
|----|--------|
| 产物路径 | `dist/index.html` |
| `dist/` 下的文件 | **只有 `index.html`**（JS/CSS 已内联，无其它文件） |
| 大小 | **145053 字节 ≈ 145.05 kB**（gzip 52.29 kB）——数字随版本微调，以 `npm run build` 的输出为准 |
| 打包模块数 | 50 modules transformed |
| 与根目录副本 | `group-chat-galgame-v2-modular.html` 与 `dist/index.html` **逐字节相同**（`cmp` 一致） |

**产物是自包含单文件**：内联一个 `<script type="module">`（bundle）与一个内联 `<script>`（启动兜底计时）；**没有**外部 `<script src>` / `<link>`。唯一的 `http(s)` 外链是「关于/素材」页里的 BGM 来源署名（`dova-s.jp` / `opengameart.org` / `itch.io`，点击才访问），外加 SVG 命名空间 `http://www.w3.org/2000/svg`。因此：**双击即玩、`file://` 可运行、离线可玩、可直接发给别人。**

### 为什么 `base` / `assetsInlineLimit` 这么配

```ts
// vite.config.ts
export default defineConfig({
  base: './',                 // 相对路径：令单文件产物可被 file:// 直接打开
  plugins: [viteSingleFile()],
  build: {
    target: 'es2022',
    assetsInlineLimit: 100_000_000, // 强制内联一切资源
    cssCodeSplit: false,            // CSS 不拆分，合成单个
  },
});
```

- `base: './'`：资源引用写成相对路径，`file://` 打开时不会去请求 `http://…/assets/…`；
- `assetsInlineLimit: 100_000_000`：把阈值抬到 100 MB，**强制**把图片/字体等一切资源内联成 data URL，杜绝任何外部引用；
- `cssCodeSplit: false`：不按模块拆分 CSS，确保最终只剩一个内联 `<style>`；
- 三者配合 `vite-plugin-singlefile`，才得到「一个文件即全部」。

> `dist/` 在 `.gitignore` 里被忽略；要分发的单文件以 `group-chat-galgame-*.html` 的形式提交在仓库根目录（当前版本是 `group-chat-galgame-v2-modular.html`）。

## 6. 校验与测试

三道关卡：`check:script`（剧本图）、`smoke`（引擎逻辑）、`check:build`（产物端到端）。

### 6.1 `npm run check:script` —— 剧本图校验

由 `src/engine/validate.cli.ts` 调用 `validateScript()`。实测输出：

```
角色 16（可攻略 15）　·　节点 1249（label 165）　·　坏结局 23　·　角色线 15
剧本校验通过：1249 个节点，0 个警告
```

| 字段 | 含义 |
|------|------|
| 角色 16（可攻略 15） | `CHARS` 的键数；含 15 名可攻略角色 + 1 名反派 |
| 节点 1249 | 展平后的**指令表长度**（`SCRIPT.length`） |
| label 165 | 命名节点（label）数量 |
| 坏结局 23 | Bad End 文案条数（`BEDATA`） |
| 角色线 15 | 好结局槽位（`GE_SLOTS`）数量 |
| 0 个警告 | 既无「节点不可达」，也无「flag 设置了但从未读取」 |

**0 错误 0 警告意味着什么**：所有跳转目标都存在、所有角色键/BE 键都能解析、没有重复 label/hub id、每个节点都可达。**错误（error）会让构建失败**：只要存在 error，`check:script` 退出码为 `1`，`npm run build` 随之中断。

错误/警告的打印格式（`formatIssues()`）：

```
✗ [goto-unknown] goto 目标不存在：some_missing_label（节点 #123）
⚠ [unreachable] 节点不可达：say（节点 #456）
```

| level | code | 触发条件 |
|-------|------|---------|
| error | `start-missing` / `start-not-first` | 缺少 `start` 标签 / `start` 不在第 0 个节点 |
| error | `label-duplicate` | label 重名 |
| error | `goto-unknown` | goto / 选项目标不存在（**最常见的剧本笔误**） |
| error | `char-unknown` | 台词说话人、立绘、好结局引用了不存在的角色键 |
| error | `be-unknown` | Bad End 缺文案 |
| error | `hub-id-duplicate` / `loop-id-duplicate` | 枢纽 / 循环选项 id 撞车 |
| error | `loop-no-arcs` | 循环中枢没有任何本命支线 |
| warn | `unreachable` | 节点从 `start` 出发不可达 |
| warn | `flag-unused` | 设置了但从没被读取的 flag |

> 历史上的 `tools/validate.js` 已被 `npm run check:script` 取代；旧 `tools/smoke-test.js` 也被 `npm run smoke` 取代，二者均不属于当前的 npm scripts。

### 6.2 `npm run smoke` —— 无头引擎测试

`tools/smoke.ts` 用一个 `FakeRenderer` 直接跑通整张剧情图，**不依赖浏览器**。实测关键输出：

```
== 1. 回合循环中枢 ==
  ✓ 首轮给全部 15 条全员支线  → 15
  ✓ 选中后锁定攻略对象 = 闹七  → "nanao"
  ✓ 锁定给一次性羁绊 +2  → 21
  ✓ 锁定后不再出现其他角色的支线  → []
  ✓ 每回合随机事件 ≤ 2  → [2,2,2]
  ✓ 每回合至少 1 个随机事件  → [2,2,2]
...
== 6. 15 条角色线 ==
  ✓ 15/15 角色线都能走到各自的 GOOD END  → "全部通过"

[SMOKE PASSED]
```

覆盖范围：

- **运营机制**：首轮给全部 15 条候选 → 锁定攻略对象（一次性羁绊 +2）→ 之后每回合只出 TA 的本命支线 + 至多 2 条随机事件 → 羁绊攒到阈值 `12` 出现「推进主线」；
- **分岔之夜**：`空気 ≥ 3` → 落「第 81 人」Bad End（`b81`）；
- **角色线失败**：选错分支 → Bad End；
- **15 条角色线**：逐条验证都能走到各自的 GOOD END；
- **存档往返**：序列化 → 反序列化、v1 老存档迁移。

结尾打印 `[SMOKE PASSED]`（失败则 `[SMOKE FAILED] n 项`，退出码非 0）。

### 6.3 `npm run check:build` —— 产物端到端测试

`tools/boot-check.mjs` 用 `jsdom` **真正加载 `dist/index.html`**，把内联的 module 源码取出后手动 `eval`（jsdom 不执行 `<script type="module">`，这是唯一一处迁就），然后驱动整局玩法。覆盖：

- 外壳挂载 / 标题页（4 个按钮、15 个角色剪影）；
- 序章推进到第一个选择、选项作答（以「我」的消息发出）；
- **复读彩蛋**：连点 3 次复读 → 触发「刷屏 END」Bad End 弹窗；
- **结局回收室**：坏结局 / 好结局两类进度、未解锁项仍被遮住；
- **第二章回合循环**：首轮 15 条候选、锁定后只出本命支线 + ≤2 随机事件、羁绊/支线进度提示；
- **群工具面板**：群成员抽屉（16 行）、回想 / 存档 / 设置 / 路线面板都能打开且有内容；
- **无控制台错误**。

实测结尾：

```
== 错误日志 ==
无 ✓

[BOOT CHECK PASSED]
```

## 8. 本地存档

存档全在浏览器 `localStorage`，**唯一允许碰它的模块**是 `src/ui/storage.ts`；引擎侧序列化/校验在 `src/engine/persist.ts`。

| 键 | 内容 |
|----|------|
| `group-gal/save/auto` | **自动存档**（每次抵达选择点自动写入） |
| `group-gal/save/s1` / `s2` / `s3` | 3 个手动槽 |
| `group-gal/settings` | 设置（BGM 开关、文字速度） |

- 前缀统一为 **`group-gal/`**；槽位 `auto` / `s1` / `s2` / `s3`。
- 引擎侧 **`SAVE_VERSION = 3`**（`src/engine/persist.ts`）。v3 新增 `stats` / `target` / `turn` / `unlocked` 等字段；**v1 / v2 老存档经 `migrateSave()` 自动补齐**（缺 `stats`、`target`、`turn`、`unlocked` 或空 `progress` 的都按新局初值补上）。
- 反序列化是**防御性**的：存档来自用户可随手编辑的 `localStorage`，属于不可信输入——**任何畸形一律返回 `null`（读不出），绝不抛错、绝不白屏**，并拒绝 `__proto__` / `constructor` / `prototype` 等原型污染键。

> ⚠️ **清缓存 = 清档**：清除浏览器数据、换域名/换文件路径、使用隐私模式都会隔离或清空 `localStorage`。设置面板里也有「清除全部存档」（带二次确认）。

## 9. 常见问题（FAQ）

| 问题 | 原因与处理 |
|------|-----------|
| **双击 `index.html` 打不开游戏** | 它是 Vite **开发入口**，`file://` 下模块加载失败，约 1.2 s 后显示兜底提示。解决：改用 `./start.sh`、双击 `group-chat-galgame-v2-modular.html`，或 `npm run dev` |
| **`npm run build` 报校验失败** | 说明剧本图有 error，构建被前置校验拦下。报错形如 `✗ [goto-unknown] goto 目标不存在：xxx（节点 #123）`——`[...]` 里是错误码，`（节点 #123）` 指出问题节点下标。到 `src/content/` 对应的剧本节点里定位并修正 `goto` / 角色键 / BE 文案即可 |
| **没声音** | 浏览器要求 Web Audio 在**用户手势**之后才能出声：先点一下页面任意处；或检查顶栏 `🔊` 与设置里的「背景音乐」。无 `AudioContext` 的环境会**安全降级为静默**（不报错） |
| **端口被占用 / 想换端口** | `./start.sh 9000`（默认 `8931`） |
| **Node 版本过旧** | 版本低于 Vite 7 / tsx 的要求时，`npm run dev` / `build` 等会直接报「Node 版本过低」并退出。升级 Node 到 **≥ 20** 即可（见第 1 节） |
| **刷新后没有进度** | 见第 8 节：存档在 `localStorage`；换路径/域名或隐私模式会隔离存储。自动存档只在抵达选择点时才写盘 |
