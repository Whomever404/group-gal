# 06 · 参考素材与内容管线

> 素材：`members.zip`（52 份 QQ 号命名的聊天记录）与 `report.pdf`（23 页综合分析报告）。
> 本文说明"真实素材 → 游戏内容"的转换关系与生产流程。

## 1. 素材一：`members.zip`

- **规模**：52 个 `.md` 文件，对应 52 名有发言记录的成员；群名册共 80 人。
- **字段**：文件名=QQ 号；正文含昵称、群名片、角色（owner/admin/member/bot）、消息条数、时间范围与逐条消息（图片/表情/合并转发/文件均有占位）。
- **覆盖区间**（据 `report.pdf`）：第一批 2026-09-26 ~ 09-29；第二批 2026-10-08 ~ 10-10；合计 5,325 条消息。中间 09-30 ~ 10-07 因 QQ 本地缓存滚动而出界。
- **格式样例**（节选自 `3433786233.md`，群主）：

  ```markdown
  # 我的弱小被你们说是狗叫，， (3433786233)
  群名片 我的弱小被你们说是狗叫，， · 角色 owner · 1153 条
  10-08 14:33 ~ 10-10 23:27
  - `10-08 14:33`  这东西开subagent是不是太猛了
  - `10-08 14:37`  [图片](https://multimedia.nt.qq.com.cn/...) 这么吊
  - `10-08 14:57`  一次开那么多agent光速花完
  - `10-08 15:05`  ↳ 回复 TheSamsara?：这么友好
  - `10-08 15:29`  [合并转发]
  ```

### 1.1 按人拆分：`dialogues/`（52 个文件）

`members.zip` 里的记录是"原始导出"（含图片直链、表情 JSON、@ 前缀等噪音）。
[`tools/split-dialogues.py`](../tools/split-dialogues.py) 把它拆成**一人一文件**的可读对话集：

```bash
python3 tools/split-dialogues.py          # members.zip → dialogues/（52 个 <昵称>_<QQ>.md + INDEX.md）
```

处理规则：

| 原始 | 拆分后 |
|------|--------|
| `[图片](https://multimedia.nt.qq.com.cn/...) 这么吊` | `[图片] 这么吊`（去链接，保留文字） |
| `[表情 {'faceIndex': 500, 'faceText': '/秋秋赏月', ...}]` | `[表情：/秋秋赏月]`（无脸名时 → `[表情]`） |
| `[video]` / `[file]` / `[语音]` / `[合并转发]` | 原样保留占位 |
| `↳ 回复 某人：…`、时间戳 | 原样保留 |
| 文本中自带的 URL（如群友发的网盘/网站链接） | 视为对话内容，保留 |

产物：

```
dialogues/
├── INDEX.md                              # 52 位群友索引（按条数排序：昵称/群名片/角色/条数/时间范围）
├── 我的弱小被你们说是狗叫，，_3433786233.md   # 1153 条（群主）
├── 黄油猫是我妈妈，_2929988459.md            # 883 条
├── …（共 52 个）
└── _comi_437345594.md                     # 1 条（边缘成员）
```

校验：拆分后总条数与源文件**逐人一致**（52 人 / 5,325 条，与 `report.pdf` 的统计口径一致）。

> 游戏 v2 的台词正是从这类对话里取材的（见 §3 角色映射表与 §4 机制映射）。

### 1.2 人设蒸馏：`skills/immortals/`（20 个包）

在对话集之上，用 [immortal-skill](../skills/immortal-skill/SKILL.md)（数字永生框架）把 **20 位群友**蒸馏成可加载的人设 Skill：

| 步骤 | 命令 | 产物 |
|------|------|------|
| 1. 拆分 | `python3 tools/split-dialogues.py` | `dialogues/`（52 人 / 5325 条） |
| 2. 语料摘要 | `python3 tools/mine-persona-evidence.py` | `skills/immortals/_evidence/<slug>.md`（高频短语 / 主题命中 / 回复对象 / 他人提及） |
| 3. 蒸馏 | 按框架 Phase 0-7（`personas/friend.md` 模板） | `skills/immortals/<slug>/`（SKILL.md + personality / interaction / memory / conflicts + manifest） |
| 4. 质检 | `python3 tools/verify-personas.py`、`python3 tools/audit-quotes.py` | 结构 / 证据纪律 / 引文溯源全绿 |

- 角色模板统一为**朋友**（`ethics_note=personal-memorial`）：正文只含本人原话（`verbatim`）与行为统计（`artifact`），他人印象一律隔离在分隔线以下。
- 索引与人物一览见 [skills/immortals/README.md](../skills/immortals/README.md)。
- 引文真实性：1,639 条原话可在 `dialogues/` 中逐字定位，0 条无法溯源。

## 5. 内容生产管线

```
① 导出        QQ 客户端导出两批聊天记录 → 按 QQ 号拆分为 52 个 md（members.zip）
② 归档归并     按 QQ 号归并曾用名/现用名；标注 owner/admin/bot；统计发言量与时间段
③ 分析画像     report.pdf：整体画像 → 活跃分层 → 逐人画像 → 关系网络 → 十大问题
④ 人设蒸馏     skills/immortals/：每位群友一包人设（语料摘要 → 口癖/立场/冲突），台词以此为依据
⑤ 结构设计     序章 + 第一章 → 第二章回合循环（锁定攻略对象 / 本命支线 / 随机事件）→
              第三、四章 → 15 条角色线 → GOOD END；坏结局 23 条
⑥ 剧本撰写     content/ 里的 DSL 节点：chat 节点还原群聊节奏、avg 节点写独白场景、选项 fx 决定羁绊与资质
⑦ 数值校准     fx 数值 → route.ts 的 PRIORITY 平票表 → 羁绊阈值 → npm run check:script 校验可达性
⑧ 验证         npm run smoke（无头跑通 15 条线） + npm run check:build（真加载产物走一遍）
⑨ 打包发布     npm run build → dist/index.html（单文件，内联 CSS/JS/SVG/合成音频）
```

> 管线里的 `tools/*.py` 是 ④ 那一步的工具：`split-dialogues.py`（拆分）、
> `mine-persona-evidence.py`（语料摘要）、`verify-personas.py`（人设包质检）、
> `audit-quotes.py`（引文溯源审计）。

## 6. 改编伦理与红线（项目自我约束）

1. **二次虚构**：游戏角色是群内可见行为的"戏剧化聚合"，关于页与报告均声明"与现实人物无关"。
2. **不搬运原始素材**：不引用 `members.zip` 中的真实头像/图片链接；立绘全部用 SVG 剪影替代（只保留 emoji 与主题色）。
3. **隐私处理**：游戏内不使用 QQ 号；真实昵称改为角色化昵称（"闹七""石蒜"等）。
4. **风险内容戏剧化但不美化**：性暗示、语言暴力等作为"可触发 Bad End 的负面选项"存在，用于呈现问题本身，而非鼓励。
5. **版权**：仅内置自合成 BGM；真实曲目（如 Arcaea 版权曲）通过"本地文件"方式由玩家自持自播，不随游戏分发。
